# Export PDF Design

## Context

Portfolio Tracker already supports CSV export of holdings (`export_holdings_csv`) and full database backup (`backup_database`), both of which write to disk without a native file dialog — CSV export triggers a browser-native Blob download inside the webview, and backup resolves a filename to `app_data_dir` with a strict path-traversal check. Neither uses `tauri-plugin-dialog`, which is not installed in this project.

Users want a polished, point-in-time PDF snapshot of their portfolio for tax prep, record-keeping, or sharing with a financial advisor — not a raw data dump. This should look like a designed document (title, summary, holdings table, allocation breakdown, footer), not a printed screenshot.

Tauri v2's webview (WRY) only implements `window.print()` support for Windows and Linux, not macOS's WKWebView, and this app is macOS-only. A frontend/browser print-to-PDF path is therefore not viable.

## Goals

- Add an "Export PDF" action to the Holdings toolbar, next to "Export CSV".
- Generate a clean, single-purpose PDF snapshot: header, portfolio summary, holdings table, asset-class allocation breakdown, footer.
- Save automatically to `~/Downloads/portfolio-YYYY-MM-DD.pdf` — no native save dialog, no new Tauri plugin.
- Show a success or error toast, matching the existing CSV export UX.
- Cover the new Rust PDF-building logic and the frontend handler with tests.

## Non-Goals

- No native Save dialog / `tauri-plugin-dialog` — deliberately out of scope per user decision, to avoid adding a new plugin dependency and keep the save path fully server-resolved (no user-supplied destination path to validate).
- No `window.print()` / webview print path — not available on macOS in Tauri v2.
- No headless browser / HTML-to-PDF rendering (e.g. headless_chrome, wkhtmltopdf) — explicitly excluded as too heavy a dependency for this use case.
- No customization of PDF contents (date range, selected holdings, per-account export) in v1 — always a full current-snapshot export.
- No historical/multi-period PDF reports — single point-in-time snapshot only.

## Approach

### PDF generation: `genpdf` (Rust)

Use the `genpdf` crate (built on `printpdf`, MIT-licensed) to generate the PDF entirely in Rust. It provides:
- `elements::TableLayout` with a pluggable `CellDecorator` trait — used to implement alternating row shading on the holdings table.
- `PageDecorator` — used for a repeating footer across pages.
- Automatic pagination when the holdings table exceeds a page.

`genpdf` requires embedded fonts (no system-font fallback). Bundle IBM Plex Sans (Regular + Bold, SIL Open Font License, ~150KB) under `src-tauri/assets/fonts/`, embedded via `include_bytes!` at compile time — matching the app's existing UI typography rather than introducing a different look for the exported document.

### Save flow: fully server-resolved path, no dialog

Mirrors the shape of `backup_database` (returns the saved path as `String`) but takes no `destinationPath` input at all, since there's no need for user-selectable location:

1. Frontend calls `tauriInvoke('export_portfolio_pdf')` with no arguments.
2. Rust command reuses the existing snapshot-building logic (`get_portfolio_impl` in `commands/portfolio.rs`) to get the current `PortfolioSnapshot`.
3. Rust builds the PDF bytes via the new `pdf::build_portfolio_pdf(&snapshot)`.
4. Rust resolves the destination as `dirs::home_dir()?.join("Downloads").join(format!("portfolio-{date}.pdf"))`, where `{date}` is `YYYY-MM-DD` (UTC, matching the app's existing ISO 8601 timestamp convention). An existing file at that path is overwritten, consistent with `backup_database`'s same-day behavior.
5. Rust writes the bytes with `std::fs::write` and returns the destination path as `String`.
6. Frontend shows a success toast including the saved path, or an error toast via `getErrorMessage(e)` — same pattern as `handleExport` for CSV.

Because no path is accepted as input, there is no path-traversal surface to validate (unlike `backup_database`, which must confine a user/frontend-supplied `destinationPath`).

### PDF content

- **Header:** "Portfolio Tracker" title, export date/time, base currency.
- **Summary:** total value, daily P&L, total gain/loss — gain/loss text colored using the same semantic tokens as the UI (`--color-gain` / `--color-loss` equivalents baked into the PDF as RGB).
- **Holdings table:** symbol, name, account, quantity, cost basis, current price, market value, gain/loss, gain/loss % — one row per holding from the snapshot, alternating row shading via a custom `CellDecorator`, spanning multiple pages automatically for long holdings lists.
- **Allocation breakdown:** Stock / ETF / Crypto / Cash weights, computed directly from the snapshot's existing `weight` and `marketValueCad` fields (no new analytics query).
- **Footer (every page):** "Generated by Portfolio Tracker" + export timestamp.

Layout: A4 portrait, generous margins, IBM Plex Sans body text, right-aligned numeric columns.

## Data Flow

```
Holdings.tsx "Export PDF" button
  → usePortfolio().exportPortfolioPdf()
    → tauriInvoke('export_portfolio_pdf')
      → commands/pdf.rs: export_portfolio_pdf command
        → commands/portfolio.rs: get_portfolio_impl (existing, reused)
        → pdf.rs: build_portfolio_pdf(snapshot) -> Vec<u8>
        → std::fs::write(~/Downloads/portfolio-{date}.pdf, bytes)
        → returns saved path (String)
  ← toast: success (with path) or error
```

## Files Touched

**New:**
- `src-tauri/src/pdf.rs` — PDF-building domain logic (mirrors `csv.rs`'s role for CSV).
- `src-tauri/src/commands/pdf.rs` — thin `#[tauri::command] export_portfolio_pdf`.
- `src-tauri/assets/fonts/IBMPlexSans-Regular.ttf`, `IBMPlexSans-Bold.ttf`.

**Edited:**
- `src-tauri/Cargo.toml` — add `genpdf`, add `dirs` if not already present.
- `src-tauri/src/commands/mod.rs` — register the new command module.
- `src-tauri/src/lib.rs` — register `export_portfolio_pdf` in `generate_handler!`.
- `frontend/hooks/usePortfolio.ts` — add `exportPortfolioPdf()` wrapper (parallel to `exportHoldingsCsv`).
- `frontend/components/Holdings.tsx` — add "Export PDF" button next to "Export CSV" in the toolbar, using a `FileText` icon (lucide-react) and a new i18n key (`holdings.exportPdf`), with a handler following the same success/error toast pattern as `handleExport`.

**Not touched:** `package.json`, `src-tauri/capabilities/default.json` — no new Tauri plugin needed.

## Testing

- **Rust unit tests (`pdf.rs`):** `build_portfolio_pdf` produces valid PDF output (`%PDF-` magic bytes, non-trivial size) for both a populated snapshot and an empty-holdings snapshot.
- **Rust command tests (`commands_tests.rs` or a `commands/pdf.rs` test module):** command-level test verifying the returned path ends in the expected filename pattern and that the file actually exists on disk after the call, using a temp `HOME` override if needed for test isolation.
- **Frontend tests:** new test(s) for the "Export PDF" button covering the success path (toast shown with saved path) and the error path (toast shown with error message), mocking `tauriInvoke`.

## Open Questions

None — all decisions in this document were confirmed with the user during design review (no dialog plugin, auto-save to `~/Downloads`, `genpdf` for generation, IBM Plex Sans embedded fonts).
